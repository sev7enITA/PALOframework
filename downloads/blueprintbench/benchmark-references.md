# Benchmark references

These references compare documented task scope and evidence, not model scores. PALO differences are maintainer interpretations, not claims of superiority or exclusive novelty. External suites were not executed for this review. Sources checked 11 November 2026.

Discovery: [terryyz/llm-benchmark](https://github.com/terryyz/llm-benchmark/blob/ffe4975fbdefd922136ae6311ac1beee480a9b0d/README.md). All 12 entries in that directory are accounted for below, alongside eight applied comparators. The directory mixes datasets, task suites, harnesses and platforms. Its historical dataset counts are not reused as current facts. Scholar Evals could not be verified at the referenced URL.

## PALO today

**Implemented:** Evidence schema, annotation consistency, raw-output binding, calculated task acceptance, structural replay and historical configuration explorer.

**Proposed study:** Procurement specification-fidelity study, independently adjudicated unseen cases, critical-rule inversion analysis and measured human correction effort.

**Open qualification work:** External preregistration/custody, independent annotation, metric calibration, proposition-bank reuse and family-aware uncertainty.

Qualified held-out results: **0**. No PALO Blueprint Index score is assigned. References do not imply affiliation, endorsement or operational integration.

| Reference and type | Evaluation target and evidence | Difference from PALO | Practice to carry forward |
|---|---|---|---|
| [HELM](https://github.com/stanford-crfm/helm) (Evaluation framework) | Broad scenario and metric coverage for foundation models. Public framework, prompts/responses inspection and leaderboards. | PALO proposes a narrower procurement specification-fidelity study. Multi-dimensional evaluation is established prior art. | Retain scenario, adapter, model and metric versions. |
| [BIG-bench](https://github.com/google/BIG-bench) (Task suite) | Collaborative tasks probing diverse language-model capabilities. Public tasks, evaluation code and published experiments. | PALO targets business-rule preservation in a reviewed specification, rather than broad capability coverage. | Use explicit task definitions and diverse independently selected cases. |
| [BigBIO](https://github.com/bigscience-workshop/biomedical) (Dataset library) | Harmonised biomedical datasets and task schemas. Dataloaders, provenance, licensing metadata and dataset documentation. | A dataset library is a reference for corpus governance, not a competing procurement-specification score. | Document source rights, schema mappings and provenance. |
| [BigScience Evaluation](https://github.com/bigscience-workshop/evaluation) (Evaluation framework) | Task-based language-model evaluation, including translation and question answering. Code, task abstractions and evaluation instructions. | PALO adds a scoped evidence contract for annotated business propositions; it has not demonstrated broader capability coverage. | Keep task-specific evaluation separate from model execution. |
| [LM Evaluation Harness](https://github.com/EleutherAI/lm-evaluation-harness) (Evaluation framework) | Configurable execution of academic language-model tasks across backends. Task configurations, model adapters, metrics and sample logging. | This is reusable execution infrastructure. PALO supplies a proposed domain-specific task and adjudication contract; no integration is claimed. | Reuse configuration discipline and record prompt, backend and generation settings. |
| [Scholar Evals](https://github.com/scholar-org/scholar-evals) (Unverified directory entry) | Scope could not be verified from the referenced repository. The referenced repository returned HTTP 404 during this review. | No capability comparison or judgement of benchmark quality is made from an unavailable source. | Preserve the discovery reference and mark unknown evidence explicitly. |
| [BigCode Evaluation Harness](https://github.com/bigcode-project/bigcode-evaluation-harness) (Coding evaluation framework) | Code generation and related coding tasks, including unit-test-based evaluation. Task implementations, generation/evaluation tooling and container instructions. | Correct code against supplied tests does not establish that the originating business requirement was interpreted faithfully. | Keep code-test outcomes separate from source-rule fidelity. |
| [Chatbot Arena / Arena](https://arena.ai/blog/ranking-method) (Preference evaluation platform) | Model comparison with uncertainty-aware score and rank presentation. Published ranking methodology and confidence/rank intervals. | PALO proposes source-based adjudication of obligations and exceptions; preference and semantic fidelity answer different questions. | Show uncertainty and avoid treating a small numerical ordering as a stable ranking. |
| [GLUE](https://arxiv.org/abs/1804.07461) (Language-understanding suite) | General natural-language understanding across multiple tasks. Task suite, analysis platform and published methodology. | PALO examines source-to-specification transformations and the correction burden within a business domain. | Use task-specific gold and publish per-task results. |
| [SuperGLUE](https://arxiv.org/abs/1905.00537) (Language-understanding suite) | More challenging general language-understanding tasks following GLUE. Benchmark tasks, evaluation methodology and analysis resources. | PALO is narrower and currently unqualified; neither general NLU performance nor PALO diagnostics imply success on the other. | Define acceptance and task difficulty before comparing systems. |
| [CLUE](https://github.com/CLUEbenchmark/CLUE) (Language-understanding suite) | Chinese-language understanding through representative classification and reading tasks. Datasets, baselines, task metrics and leaderboards. | PALO has not qualified multilingual specification fidelity. Country of model origin is not a language-quality measurement. | Treat language and localisation as explicit evaluation conditions. |
| [CodeXGLUE](https://github.com/microsoft/CodeXGLUE) (Code-intelligence suite) | Code understanding and generation, including code/text transformations. Task datasets, baselines and evaluation resources. | PALO proposes checking the business meaning before code is produced; code/text overlap is acknowledged. | Separate transformation types and use outcome-appropriate metrics. |
| [Vals AI](https://www.vals.ai/benchmarks) (Applied evaluation platform) | Industry-oriented tasks and model comparisons across professional domains. Published benchmark pages and methodologies; some benchmarks are proprietary. | Enterprise evaluation is already established. PALO proposes a specific document-to-specification fidelity study, without claiming broader coverage or superior validation. | Use realistic tasks and make public/private evidence boundaries explicit. |
| [Artificial Analysis](https://artificialanalysis.ai/methodology) (Evaluation platform) | Quality, intelligence, performance and price of models, endpoints and systems. Published measurement definitions and comparative results. | PALO records configuration-specific evidence and proposes workflow correction effort; current cost records are not full enterprise cost measurements. | Distinguish model, serving endpoint and complete system. |
| [OfficeQA](https://github.com/databricks/officeqa) (Document-reasoning benchmark) | Complex questions over real-world financial documents. Evaluation code and corpus tooling; source documents, parsed data and gated answer sets are documented. | A close comparator. PALO proposes evaluating the resulting specification and altered rules, rather than only answers to questions. | Separate parsing, retrieval and reasoning; keep unseen document families. |
| [DABstep](https://huggingface.co/blog/dabstep) (Data-agent benchmark) | Multi-step business data analysis with factoid answers. Tasks, answer-format requirements and automated answer checks. | PALO propositions can admit multiple legitimate formulations and require semantic adjudication; answer normalisation alone is insufficient. | Use deterministic checks where valid, without confusing formatting with correctness. |
| [OmniDocBench](https://github.com/opendatalab/OmniDocBench) (Document-parsing benchmark) | Document parsing, including text, tables, formulas and layout. Annotated document data and evaluation tooling. | Parsing is an upstream component; PALO proposes checking whether extracted content retains its business meaning in a specification. | Measure extraction independently from interpretation. |
| [SWE-bench Verified](https://www.swebench.com/verified) (Software-agent benchmark) | Resolution of repository issues using a human-validated task subset. Task definitions, evaluation resources and published agent results. | PALO focuses on interpreting the source requirement before implementation; passing software tests addresses a different evaluation stage. | Freeze the harness and distinguish model comparisons from whole-agent comparisons. |
| [FACTS Grounding](https://arxiv.org/abs/2501.03200) (Grounded-generation benchmark) | Factual grounding of generated responses in supplied documents. Published benchmark and multi-judge evaluation methodology. | A close semantic comparator. PALO proposes domain-specific critical-rule inversions and human repair effort; that additional value still needs validation. | Calibrate semantic judging against independent reference decisions. |
| [Andon Labs Blueprint-Bench 2](https://andonlabs.com/evals/blueprint-bench-2) (Spatial-reasoning benchmark) | Reconstruction of apartment floor plans from photographs. Published task description, connectivity metric and leaderboard. | Distinct project and meaning of blueprint: spatial floor plans versus business development specifications. No affiliation or shared score. | Disambiguate the name and compare only commensurate tasks. |

- **Chatbot Arena / Arena:** Current methodology checked; directory points to historical FastChat infrastructure. [Source](https://arena.ai/blog/ranking-method).
- **GLUE:** The directory links jiant, an implementation toolkit whose README says it is no longer actively maintained. [Source](https://arxiv.org/abs/1804.07461).
- **SuperGLUE:** Distinguish the benchmark from the jiant implementation linked by the directory. [Source](https://arxiv.org/abs/1905.00537).

[jiant maintenance notice](https://github.com/nyu-mll/jiant) supports the implementation-status distinction for GLUE and SuperGLUE. The [earlier methodological review](research.md) retains additional references, including process modelling, spreadsheet tasks, agent security and contamination.
