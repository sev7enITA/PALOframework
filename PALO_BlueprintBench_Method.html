Research method

Method

The unit of evaluation is a configured system performing a defined document task.

Model identity alone does not describe an experiment. The request, source material, serving provider, reasoning setting, output limit, parsing contract and review procedure affect the observed result.

Evidence status

Published observations are maintainer-led tests with provisional labels and automated advisory review. Independent human adjudication and validation are pending. No qualified quality ranking or PALO Blueprint Index is assigned.

Tasks and evidence

Statement verification

A source text and candidate statement are supplied together. The system classifies whether the statement is supported, contradicted, not established, or affected by an unresolved conflict where the test rubric permits it.

Specification generation

The system proposes entities, rules and process decisions from the source. Outputs retain references so reviewers can assess meaning, missing requirements and unsupported additions.

Controlled variations

Document order or a stated condition is varied. Relations between paired outputs are examined. A variation that also changes the question batch cannot isolate a single causal factor.

Result Interpretation

Fixed assignments and missingness

Assigned requests remain in the record when they fail or are not run. Missing output, rejected structure and disagreement with a provisional label are different outcomes. No missing charge is converted to zero.

Structure and meaning

A valid JSON object or source reference can still express the wrong rule. Structural acceptance is a contract check. Label agreement is descriptive until the labels and rubric have been adjudicated independently.

Costs, time and context

Reported token usage and charges describe the retained requests. Maximum configured output and advertised context capacity are separate from observed prompt length. Different tokenisers, settings and scheduling prevent uncontrolled efficiency rankings.

Disputes and changes

Frozen primary labels remain visible. Predeclared exclusions, postrun ambiguity notes and sensitivity analyses are identified separately. Model agreement is advisory evidence, not majority-vote gold.

Execution and provenance

The model-result studies use the OpenRouter API, with the serving provider recorded separately where the receipt supplies it. A provider pin and the returned provider are not the same field. Missing identity details remain unavailable. These API measurements do not establish local hardware performance.

Reviewer diagnostics use separate collection channels, including APIs, a browser, desktop applications and a local model server. Their prompts and observation conditions differ from those used to produce the model results. Review those diagnostic records separately.

In this method, a test identifies the input set and task. A run is one recorded execution. A configuration identifies the model and serving settings. Archived files may retain older terms such as campaign or case; those identifiers do not create additional independent datasets.

Requirements for independent validation

  1. Domain experts construct and adjudicate reference propositions, including alternatives and prohibited inferences.
  2. An external custodian retains source sets outside the system-development process.
  3. The measure is tested against known semantic defects and false alarms.
  4. Repeated runs use an appropriate sampling design and uncertainty analysis.
  5. An independent party reproduces the evaluation and signs the review record.

These requirements are pending. Automated reviews can identify problems, but cannot substitute for independent domain expertise or custody. Inspect the qualification roadmap.

Governance and limitations

PALO maintains both Workbench and BlueprintBench. That relationship is a declared conflict of interest. The current observations do not certify Workbench, demonstrate organisation-wide document processing, or establish a production governance control. Source reuse conditions and provider-specific configuration limits remain part of each evidence record.

The evaluator release and the presentation revision have separate identities. Historical evidence retains its original bytes. The earlier evaluator 0.2 package is not the corrected evaluator. Inspect versioned releases.

Priorities for PALO

Expert gold and atomic rubrics

Recruit procurement experts, freeze allowed alternatives and forbidden inferences, adjudicate disagreements and report human agreement before qualification.

References: GDPval, DeepResearch Bench / II, GPQA / Diamond. Proposed work; not completed qualification.

End-to-end workflow reliability

Test document import, interpretation, human correction and blueprint export with repeated runs, environment identity, failure states and cost/time accounting.

References: tau2-bench, OSWorld, Terminal-Bench. Proposed work; not completed qualification.

Structural and Semantic Assessment

Report schema/tool validity, source support, semantic violations and downstream executable checks as separate outcomes.

References: Berkeley Function Calling Leaderboard, SWE-Bench Pro, BrowseComp. Proposed work; not completed qualification.

Freshness, custody and disclosure

Use externally selected unseen families, date windows, protected answer custody, sponsor/data-access disclosures and versioned judge/adapter policies.

References: LiveCodeBench, Humanity's Last Exam, ARC-AGI, FrontierMath. Proposed work; not completed qualification.
